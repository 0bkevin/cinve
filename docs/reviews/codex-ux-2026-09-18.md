# Evaluación de experiencia en Codex — 18/09/2026

Se probó Codex CLI/app-server 0.155.0 en conversaciones nuevas fuera de este
repositorio, usando la guía pública de instalación de Cinve y el MCP de
producción. Primero se eliminaron la entrada guardada del servidor y la sección
de instrucciones de usuario de Cinve. No había credenciales OAuth de Cinve ni
sesiones locales de cines. Los demás servidores MCP se conservaron. No se usaron
credenciales reales de cines.

## Escenarios reales de conversación

| Consulta o escenario | Comportamiento observado |
| --- | --- |
| Instalar desde `https://cinve.vercel.app/install` | Registró Cinve y guardó las instrucciones de usuario. La recomendación anterior de `codex mcp add` inició el OAuth opcional y superó el límite de 20 segundos del subproceso instalador. El asistente se recuperó revisando la configuración y probando el MCP directamente. |
| Películas de hoy en Cines Unidos de Caracas | Usó las herramientas de proveedor, ciudad, sede, película y función. Devolvió una selección concisa con la fuente, sin pedir login ni desviarse a una búsqueda web. |
| Películas de hoy sin ubicación | Preguntó ciudad y país en vez de asumir una ubicación. |
| Caramelería de Cines Unidos Sambil Caracas | Usó los datos públicos e indicó explícitamente que no hacía falta una cuenta. |
| Conectar Cines Unidos para consultar precios | Llamó `connect_account`, inició `codex mcp login` y mostró una URL real de autorización, sin enviar al usuario a Configuración ni buscar en la web. |
| Conversación persistente después de mostrar la URL | Se comprobó que el listener de callback seguía activo al terminar el turno del asistente. Un proceso aislado de `codex exec` cierra sus subprocesos al salir y no sirve para comprobar esta entrega. |
| Cancelar la conexión pendiente | El asistente confirmó la cancelación y no quedó ningún proceso o listener de login. |

## Pruebas integrales con cuenta sintética

La comprobación repetible `npm run test:codex-auth` inicia un clúster PostgreSQL
aislado y un servidor alojado local con un autenticador de cine sintético. Usa
un hilo efímero de Codex app-server y un nombre MCP temporal pasado mediante
opciones del CLI. Al terminar elimina las credenciales de prueba y la base de
datos. No invoca un modelo ni conecta una cuenta real.

Se observó y verificó lo siguiente:

- La aprobación en el navegador completa correctamente el callback OAuth y el
  intercambio de tokens del Codex CLI instalado.
- El formulario privado del cine guarda la sesión sintética del proveedor.
- Autorizar el CLI no actualiza un transporte anónimo de Codex que ya esté en
  ejecución. Repetir `connect_account` seguía sin devolver un enlace de cine.
- `config/mcpServer/reload` permite que el hilo existente reconozca al cliente
  autorizado y la cuenta conectada.
- `mcpServer/oauth/login`, con el identificador del hilo, emite una notificación
  de finalización y permite usar `connect_account` en el mismo hilo sin otra
  recarga.
- El callback del CLI de Codex devuelve HTTP 400 ante la redirección estándar de
  rechazo OAuth y deja el comando esperando. La prueba detiene ese proceso. Es
  una limitación del cliente, no una cancelación completada correctamente.

## Cambios derivados de los hallazgos

- La guía instala el acceso anónimo de Codex editando solo la tabla TOML de
  Cinve; ya no recomienda la ruta `mcp add`, que inicia autorización automática.
- `get_auth_status` identifica si el asistente que llama está autorizado de
  forma independiente al estado de las sesiones de cine. Para clientes anónimos
  el estado es `client_authorization_required`, no el ambiguo `missing`.
- Las instrucciones compartidas priorizan la autorización nativa, mantienen
  vivo el callback, muestran la URL de inmediato, observan la finalización,
  detienen intentos cancelados y recargan una vez después de autorizar por CLI.
- Los asistentes no deben inventar herramientas nativas del host. Si el host no
  expone login ni recarga de conexiones, sigue siendo necesario reconectar.

## Límites

No se inició sesión en una cuenta real de cine ni se consultaron precios
privados. El diseño visual del navegador no se revisó; los formularios y
callbacks se ejercitaron por HTTP. La integración nativa de app-server funciona,
pero un MCP remoto no puede obligar a todos los clientes a exponer esas acciones.
Estos resultados no garantizan una experiencia universal sin reconexiones.
